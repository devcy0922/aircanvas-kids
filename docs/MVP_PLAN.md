# 개발 계획 — S-Kids MVP

작성 기준: 2026-10-14. 이 문서는 제안하는 단계별 계획이며 **기능 구현 완료를 의미하지 않는다.**

## 목표

3가지 핵심 필터(자치구, 내 위치 반경, 아이 이용 연령)로 서울형 키즈카페를 검색하고, **가능한 경우** 5분 캐시 기반 회차별 예약현황과 수동 새로고침을 제공한 뒤 **공식 예약 페이지**로 이동한다.

성공 기준은 서비스 복잡도가 아니라 검색 정확도·현황 데이터 정확도·안전한 호출 정책·모바일 가독성이다.

## Phase 0 — 제공 권리·접근성 검증 (가장 우선)

- [ ] 시설현황 공공데이터 API 응답 스키마, 제공 건수, 매핑 필드 확인
- [ ] 3~5개 지점의 공식 예약 URL/시설 ID를 수동 확보
- [ ] 해당 페이지의 회차 숫자 표기와 선택 후 이용가능 수치 교차 검증
- [ ] 현 페이지가 서버 렌더 HTML인지 별도 XHR 데이터인지 확인
- [ ] 공개 페이지의 로그인/세션/응답 상태·redirect·robots 정책 확인
- [ ] 자동 수집·외부 재표시 허용, 접근빈도, 상업적 이용 조건 운영기관 문의
- [ ] 403/429/CAPTCHA 등 접근 제한 확인 시 우회하지 않고 PoC 중단
- [ ] 확인 결과를 `docs/LEGAL_AND_ROBOTS.md`와 PoC 증빙에 남김

**Phase 0 완료 조건:** ① 적법한 조회·재표시 근거가 확인되었는지, ② 수치의 의미가 정확히 정의되었는지, ③ 5분/수동 갱신이 사이트에 부담을 주지 않는지. 하나라도 불합격이면 가용현황 수집 기능을 보류.

## Phase 1 — 시설 탐색 MVP (수집과 독립 구현 가능)

- [ ] 시설 기본정보 수집·정규화 (공공데이터 조건 및 출처 표기 준수)
- [ ] 시설과 공식 상세/예약 URL 매핑 (검증 여부 필드 포함)
- [ ] 주소 지오코딩·좌표 등록·거리 계산
- [ ] 자치구 단일/다중 선택
- [ ] 위치 기반 반경 1/3/5/10km 및 위치 권한 거부 fallback
- [ ] 이용 연령 규칙(개월/연나이/예외) 원문 대조 및 경계값 테스트
- [ ] 날짜 선택 UI
- [ ] 모바일 카드 목록과 공식 예약 사이트 바로가기
- [ ] 비공식 서비스 안내/출처 표시/개인정보 최소 수집

**Phase 1 완료 조건:** 위치·연령·지역구에 부합하는 시설을 찾고 공식 예약 페이지로 이동할 수 있다.

## Phase 2 — 승인된 범위의 예약현황

- [ ] 시설 Registry (`source`, `facility_id`, `reservation_url`, `fetch_strategy`)
- [ ] 허용된 조회 경로에 대한 adapter 구현
- [ ] 파서 fixture 준비: 공용/개인/단체, 0·양수, 휴관, 미오픈, 프로그램 등
- [ ] 날짜·회차별 자료 정규화 및 UNKNOWN fallback
- [ ] 5분 TTL 캐시 + last_checked_at + stale 표시
- [ ] 사용자 새로고침 API (지점 단위) + global cooldown + singleflight
- [ ] 403/429 발생 시 중단, 회로차단기, 호출량 제한, 진단 로그
- [ ] 원본과 수치 비교 자동/수동 점검
- [ ] 실패 시 현황을 마감으로 오표시하지 않음

**Phase 2 완료 조건:** 5개 이상 테스트 지점에서 회차/날짜별 데이터가 원본과 정확히 일치하며, 새로고침 동시 요청도 외부 호출 하나로 합쳐진다. 실제 운영 주기는 허용 한도에 종속.

## Phase 3 — 서비스 품질 개선 (선택)

- [ ] 여러 자치구 + 반경 + 이용 연령 동시 검색 테스트
- [ ] 검색 우선순위 실험(거리/예약 가능 여부)
- [ ] 데이터 신선도/오류율/429 지표 대시보드
- [ ] 운영자가 파서/시설 매핑 수정할 수 있는 관리 도구
- [ ] 시설 신규 등록·폐쇄·URL 변경 탐지
- [ ] 접근성·모바일 성능 점검

## 기술 선택 (미확정, 가벼운 시작 권장)

- Frontend: React / Next.js 후보
- API/Collector: Node.js/TypeScript 또는 Python 중 한 언어로 시작해 운영 단순화
- DB: PostgreSQL, 위치 검색은 규모에 따라 PostGIS 적용
- Cache/Queue: 초기에는 DB+in-process 제어도 가능, 분산 배포 전 Redis singleflight/락 검토
- 배포: Docker Compose 단일 인스턴스로 먼저 정확성과 데이터 정책 검증

## 필수 테스트

| 시나리오 | 기대 결과 |
| --- | --- |
| 오늘은 휴관 | CLOSED, 마감으로 표현 금지 |
| 예약 오픈 전 | NOT_OPEN |
| 0이지만 대기 예약 가능 | 원문 규칙에 맞게 별도 상태 또는 UNKNOWN |
| 사이트 응답 구조 변경 | 파싱 오류, UNKNOWN |
| TTL 초과 후 API 장애 | 기존 데이터는 STALE로 표시 + 경고 |
| 사용자 50명이 같은 시설 새로고침 | 외부 요청 중복 방지 |
| 새로고침 버튼 연타 | 서버 throttling, 기존 캐시 응답 |
| 아이 나이가 경계 조건 | 명시된 이용 연령 규칙 기준 계산 |
| 위치 사용 거부 | 자치구 필터만으로 탐색 가능 |
| 예약 클릭 | 사전 검증한 공식 URL만 열기 |
| 403/429/CAPTCHA | 자동 중단/감속 및 로그, 우회 금지 |

## MVP 릴리스 판단

**출시해도 되는 것:** 공식 공공데이터 기반 시설 목록, 지역·반경·연령 검색, 예약 링크.  
**아직 출시 근거가 없는 것:** 예약 가능 숫자의 지속적 자동 수집·재표시. Phase 0의 법적·기술적 확인을 먼저 통과해야 한다.
