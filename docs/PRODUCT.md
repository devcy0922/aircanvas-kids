# S-Kids 제품 요구사항(PRD)

- 작성 기준: 2026-10-14
- 단계: MVP 기획, 개발 전
- 제품 정의: **서울형 키즈카페 이용 조건과 예약현황을 한 곳에서 비교하는 비공식 검색 도구**
- 예약/결제/계정 관리: 서울시 공식 예약 사이트에 위임

## 1. 문제와 핵심 가치

### 사용자 문제
- 거주 구역 근처의 시설을 찾기 위해 여러 화면을 이동해야 한다.
- 시설별 이용 가능 연령과 시간표가 달라 비교가 어렵다.
- 원하는 날짜의 회차별 예약 현황을 각 지점 페이지에 들어가서 확인해야 한다.

### 가치 제안
> 우리 아이가 이용할 수 있는 가까운 서울형 키즈카페 중, 원하는 날 예약 가능성이 있는 곳을 빠르게 찾는다.

**차별화 포인트**는 단순 시설 지도보다 **연령·위치·회차별 잔여 현황의 합산 검색**이다. 단, 잔여 수집이 허용되지 않으면 차별화가 축소되며 별도 검증이 필요하다.

## 2. 사용자 대상과 주요 시나리오

- 영유아 부모/보호자, 주말에 이용할 시설을 찾는 가족
- 집 주변 3km와 동작구/관악구를 함께 검색
- 2세 아이가 이용할 수 없는 시설을 자동 제외
- 토요일 오전에 예약 가능한 회차를 빠르게 비교
- 예약은 공식 사이트에서 완료

## 3. 검색 UX

### 핵심 필터 3개

1. **자치구**: 전체 / 복수 자치구 선택. 첫 화면에서 과도한 선택 UI 피하기
2. **내 위치 반경**: 1 / 3 / 5 / 10km. 위치 권한 거부 시 자치구 중심 검색으로 대체; 위치 계산 불가 시 '거리 미제공' 표시
3. **이용 연령**: 아이 나이. 시설별 최소·최대 나이의 산정 기준(개월/연령/생년월일 및 보호자 동반)을 공식 상세에서 확인해야 함. 경계값 애매하면 '연령 확인 필요'로 표시

### 부가 입력
- 이용 날짜: 필수 조회 범위. 기본값은 오늘이나 가장 가까운 주말 중 UX 테스트로 결정
- 회차 필터는 v0.1에서 필수 아님. 결과 카드에서 각 회차의 상태·가능 인원을 바로 노출
- 시설별 운영일 및 예약 오픈 정책은 원문 우선

### 카드 예시 (수치는 목업이며 실제 예약 현황 아님)
```text
[서초구 예시 키즈카페]            2.1km
이용연령: 0~6세 (예시)
토요일
1회차 8명 가능 | 2회차 3명 가능 | 3회차 마감
마지막 확인: 5분 전   [새로고침]
                          [공식 예약하기 ↗]
```

**거짓 정확성 금지:** 사이트가 제공하는 수치가 실제 잔여 '명/자리'인지, 개인·단체별 가용 인원인지 PoC에서 검증하기 전에는 '8석'으로 단정하지 않는다. 필요한 경우 '공식 달력 표시 수치: 8'로 표현한다.

## 4. 상태 모델

예약 가용성을 단순한 boolean으로 표현하지 않는다.

| 상태 | UI | 조건 |
| --- | --- | --- |
| AVAILABLE | '예약 가능: N명' (단위 검증 뒤) | 공식 데이터에 유효한 양수 및 예약 가능 표시 |
| FULL | '마감' | 명시적으로 0이거나 예약 불가가 확인됨 |
| NOT_OPEN | '아직 예약 전' | 예약 오픈 전임이 확인됨 |
| CLOSED | '휴관' | 휴일/임시휴관/자체휴회 표기 |
| UNKNOWN | '확인 불가' | 조회 실패, 파싱 실패, 아직 미확인 또는 정의되지 않은 상태 |
| STALE | '오래된 정보' | 정책보다 오래된 캐시값 (원래 상태와 별도 freshness 플래그 권장) |

**빈 날짜 = 마감이 아님.** 예약 미오픈, 운영 중단, 오류 등과 구분한다.

## 5. 수동 갱신 UX

- 각 시설 카드에 '새로고침' 버튼과 '마지막 확인 HH:MM' 표시
- 클릭 시 현재 시설 + 보고 있는 날짜 범위만 갱신 요청
- 동일 시설의 다른 사용자가 이미 갱신 중이면 그 작업을 공유
- 너무 이른 재요청은 서버가 막고 '최근 확인한 내용'을 표시
- 403/429/접근 제한 또는 수집 미승인 상태에선 버튼을 비활성화하거나 공식 예약으로 연결
- 사용자에게 '실시간', '자리가 확보됨', '예약 보장'으로 표시하지 않음

## 6. 화면 구성

1. **탐색 화면**: 상단 3개 필터 + 날짜, 리스트 기본, 지도는 선택사항
2. **시설 카드**: 이름·자치구·거리·이용연령·회차별 현황·기준시각·공식 예약 버튼
3. **시설 상세(선택)**: 운영 시간, 주소, 휴관일, 원문 링크, 수집 상태
4. **오류/제한 안내**: 현재 현황 미확인/마지막 조회 시각/공식 예약 이동

모바일 우선. 기본 정렬은 거리(위치 사용 가능할 때), 대안은 예약 가능한 회차가 있는 시설 우선. 점수/추천 알고리즘은 MVP 범위 외.

## 7. 범위 밖

- 회원가입, 서울시 로그인 대행/자동 로그인
- 예약·대기·취소·결제 자동화
- 좌석 확보 또는 결제 자동 진행
- 사용자 아이의 생년월일·민감한 개인정보 영구 저장
- 상시 초단위 실시간 수집 및 무제한 강제 갱신
- 공식 UI 전체 복제 및 공식 서비스로 오인시키는 브랜딩

## 8. 수용 기준 (Acceptance Criteria)

- [ ] 서울형 키즈카페 시설을 서울시 공공데이터 기반으로 탐색
- [ ] 선택 자치구와 위치 반경을 결합하여 검색
- [ ] 시설 상세 기준으로 아이 나이의 적격/부적격/검증필요 분류
- [ ] 기준 날짜별·회차별 현황 상태를 정확하게 정규화 (수집 허가 이후)
- [ ] 검색 결과에 마지막 확인 시각을 노출
- [ ] 동일 지점 수동 갱신은 서버에서 중복 요청 병합
- [ ] 요청 한도·미승인·파싱 실패 시 정확한 실패 상태 출력
- [ ] 실제 예약 버튼은 확인된 공식 예약 페이지로 이동
- [ ] 개인정보 수집 없이 기본 검색을 제공
- [ ] 모바일 360px 폭에서도 필터/카드/버튼을 사용할 수 있음
