# 법적 검토·봇 차단·운영 정책 확인

> **검토일 2026-10-14 / 잠정 조사 결과.** 이 문서는 제품 구축 시 확인해야 할 규제·운영 리스크를 정리한 내부 기록이며, 법률 자문 또는 자동 수집 적법성의 확정 판단이 아니다.

## 1. 현재 확인된 사실과 미확인 사항

| 검토 항목 | 상태 | 근거·한계 |
| --- | --- | --- |
| 서울형 키즈카페 공식 시설현황 데이터 존재 | 확인 | 서울 열린데이터광장 OA-21716 |
| 시설현황 데이터의 공공누리 1유형 | 확인 | 출처 표시를 전제로 상업적 이용·변경 가능 |
| 개별 시설 예약 달력의 공개 숫자 표기 | 확인 | 우리동네키움포털 예시 페이지에 일자·회차별 숫자 노출 |
| `q_fcltyId` 매개변수 이용 | 일부 확인 | 일부 예약 URL에서 시설 식별값 관찰 |
| 프로그램에 의한 비로그인 HTTP 조회 | 미검증 | 검색 엔진이 읽는 것과 독립 크롤러 HTTP 접근은 다름 |
| `robots.txt`, WAF, CAPTCHA, 403/429 정책 | 미검증 | 직접 HTTP 헤더/Network 분석 완료되지 않음 |
| 공식 예약현황 제공 API | 미검증 | 공식 문서화된 API 확인되지 않음 |
| 예약현황 반복 수집·상업적 재표시 허용 | **미확인** | 운영기관의 제공 조건/허락 검토 필요 |

'웹페이지가 공개되어 있다'는 이유로 '지속적인 자동 수집과 재배포가 허용된다'고 결론 내리지 않는다.

## 2. 구별해야 할 데이터 사용 권리

### 서울시 시설현황정보

- [서울 열린데이터광장 시설현황정보](https://data.seoul.go.kr/dataList/OA-21716/S/1/datasetView.do)
- 제공기관/저작권자: 서울특별시
- 저작물 이용허락: **공공누리 제1유형** — 출처표시, 상업적 이용 및 변경 가능
- 시설명·위치·운영일·이용정원 등 공공데이터 이용 시 출처 표기
- 출처 표기 예시: `시설 기본정보 출처: 서울특별시 서울 열린데이터광장, 서울형 키즈카페 시설현황정보`
- [공공누리 1유형 공식 안내](https://www.copyright.or.kr/gov/nuri/guide/index.do)

### 서울시 예약 달력의 가용 현황

- **별도 데이터 사용 조건 검토 필요.**
- 시설현황 데이터셋에 부착된 공공누리 1유형을 개별 예약 페이지의 모든 표·숫자·HTML에 자동 적용하지 않는다.
- 숫자 자체의 저작물성 문제와 별개로, 반복 추출로 인한 데이터베이스 권리·약관·접근 제한·서버 부하 문제가 발생할 수 있다.
- [저작권법 제93조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1033063991): 데이터베이스의 상당 부분 복제·전송 등에 관한 권리, 비상당 부분이라도 반복적/체계적 추출로 통상적 이용을 해치는 경우에 관한 규정.
- 침입·접근통제 우회·서비스 방해에 해당하는 행위는 별도의 법적 위험이 있으므로 금지한다.
- 서울 열린데이터광장과 우리동네키움포털은 서로 **동일한 이용조건이 적용된다고 단정할 수 없다.**

**잠정 판단:** 시설 검색·지도 개발의 이용허락 근거는 확인되지만, 예약현황 5분 주기 수집과 공개 재표시의 허용은 확정되지 않았다.

## 3. 봇 차단·기술적 접근 확인 절차 (소량·합법적 PoC)

1. 공식 공개 페이지에서 확인 가능한 정보와 로그인 요구 구간을 분리한다.
2. `robots.txt`, 사이트 이용약관, 공식 FAQ, 공공데이터 제공범위를 확인한다.
3. 소수(3~5곳) 시설만 대상으로 브라우저 DevTools Network에서 정상 조회의 HTML/Fetch/XHR, 세션 의존성, 상태코드를 확인한다.
4. 동일한 공개 URL에 대해 허용된 범위에서 **최소 요청**으로 HTTP status/headers/redirect를 확인한다.
5. 숫자 표기와 실제 UI의 회차 선택 상태가 일치하는지 수동 교차 검증한다.
6. 401/403/429/CAPTCHA/WAF 챌린지/로그인 강제가 확인되면 자동 조회를 중단하고 사용 허가·공식 API 제공을 문의한다.
7. 호출 빈도, 상업적 이용/재표시, 봇 정책, 사용 중단 연락처를 문서화한다.

예시 명령(운영기관이 허용하는 정상 공개 페이지 확인 목적, 무제한 반복 실행 금지):

```bash
curl -i --max-time 10 https://umppa.seoul.go.kr/robots.txt

curl -sS -L --max-time 10 -D headers.txt -o reservation.html \
  'https://umppa.seoul.go.kr/icare/user/kidsCafeResve/BD_selectKidsCafeResveCal.do?q_fcltyId=SC240801'
```

`robots.txt`가 없거나 200 응답이 나오는 것만으로 수집 허가가 되지는 않는다.

**하지 않는 것**: CAPTCHA 회피, IP/프록시 회전으로 속도 제한 우회, 위조 쿠키/비인가 세션 이용, 로그인 자동 대행, 차단 후 무단 재시도, 트래픽 과부하, 예약자 명단 수집.

## 4. 운영기관 확인이 필요한 질문

- [ ] 공개 예약 달력의 **날짜·회차·예약가능 숫자**를 자동 조회해도 되는가?
- [ ] 외부 서비스에서 이 숫자만 요약 표시하고 공식 예약 URL로 연결해도 되는가?
- [ ] 유료/광고/비상업 서비스별 제한이 다른가?
- [ ] 별도 공식 API 또는 공공데이터 제공 신청 경로가 있는가?
- [ ] 허용 호출 간격, 동시 요청 수, 일일 한도는 얼마인가?
- [ ] 시설 ID/예약 URL 및 회차 데이터의 버전 변경 공지 방법이 있는가?
- [ ] 필수 출처·면책 문구와 운영기관의 중단 요청 채널은 무엇인가?

문의 경로: [우리동네키움포털](https://umppa.seoul.go.kr/), [서울 열린데이터광장 공공데이터 제공신청](https://data.seoul.go.kr/) 또는 [공공데이터포털](https://www.data.go.kr/). 시설 기본정보 담당 연락처는 데이터셋의 공식 안내에서 확인 가능.

문의 회신은 날짜·담당부서·허용범위·갱신 상한·문서 링크를 내부 증빙으로 저장하며, 개인정보 및 담당자의 직접 연락처 등 불필요한 정보를 공개 커밋하지 않는다.

## 5. 배포 전 Go/No-Go

### 자동 수집 활성화 Go
- [ ] 수집 및 재표시가 허용된다는 명확한 근거 확보(약관/공식 지침/서면 답변)
- [ ] 요청량이 허용된 한도 이내이며 자동 차단 회피가 필요하지 않음
- [ ] 날짜·회차별 의미·단위 검증, 파서 테스트 통과
- [ ] 실패·미오픈·마감 상태가 혼동되지 않음
- [ ] 출처 표기 및 비공식 서비스 안내·개인정보 최소화 완료

### No-Go 또는 범위 조정
- 사이트가 자동 수집 금지/차단 정책을 명시
- 운영기관이 재표시를 허용하지 않음
- 숫자의 의미가 불명확하거나 정확도가 낮음
- 규칙적인 조회로 429/차단/상당한 부하 발생

No-Go 시 시설/연령/자치구/위치 검색과 **공식 예약 바로가기**만 제공하고, 예약현황은 '공식 사이트에서 확인'으로 대체.
