6. **도구:** `tools/fake-phone-sim.mjs`(원/리사주 궤적 시뮬레이터), `tools/smoke-relay.mjs`(릴레이 자동 검증).

## 다음 세션이 알아야 할 것 (중요)

### Windows 빌드 환경 특이사항
- 이 PC엔 MSVC Build Tools가 없다. Rust는 **GNU 툴체인** 사용:
  - `rustup toolchain install stable-x86_64-pc-windows-gnu` 완료됨
  - rustup 셀프컨테인드 dlltool은 내부 `as.exe` 부재로 실패 → **WinLibs(winget) 설치 완료**, 빌드 시 mingw64/bin을 PATH 선행 등록해야 함
  - 루트 `package.json`의 `server:*` 스크립트에 `+stable-x86_64-pc-windows-gnu` 지정 반영됨
- PowerShell 프로파일 문제인지 Write 직후 파일이 보이지 않는 현상이 한 번 있었음(재작성으로 해결). 이상 시 `Test-Path`로 먼저 확인할 것.

### 실행 방법 요약
```powershell
$mingw = "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\BrechtSanders.WinLibs.POSIX.UCRT_Microsoft.Winget.Source_8wekyb3d8bbwe\mingw64\bin"
$env:PATH = "$mingw;$env:PATH"        # cargo GNU 빌드용
npm run server:run                     # :8080
npm run dev:tv                         # :5173 (TV/PC 브라우저)
npm run dev:phone                      # :5174 (폰 브라우저, ?server= 로 PC IP 지정 가능)
```

### 남은 갭 (M2로 넘어감)
1. **실기기 E2E**: 아이 손 기준 추적 안정성(조명/거리)은 현장 테스트만이 답. 캘리브레이션 재투영 오차 <1.5% 목표.
2. **폰 카메라 권한**: LAN IP http 제한 → chrome flag 우회법 README 참조, 정식은 basic-ssl/Caddy.
3. **pinch 활용**: 프로토콜/추적엔 이미 있고, TV 엔진의 stroke-start/end와 연결만 하면 됨.
4. **호모그래피 UX**: 현재 조준식(십자 캡처) 4점 방식. 자동 마커 인식은 M2 검토.

## 이후 세션 추가 작업 (2026-08-24)

### QR 온보딩 (완료)
- TV 홈 화면이 `qrcode` 패키지로 폰 연결 URL을 QR 렌더링: `phoneJoinUrl()` = `<폰앱>/?server=<릴레이>&room=<코드>`
- 폰 앱은 `?room=` 파라미터 감지 시 **자동 입장**(저장된 캘리브레이션이 있으면 바로 play, 없으면 calib)
- 수동 방 코드 입력 폴백 유지
- TV 앱에 `?server=`, `?phoneApp=`/`?phonePort=` 오버라이드 파라미터 추가 — 상대경로 WS 버그도 함께 수정
- 검증: tv/phone 빌드 통과

### 폰 주도 테마 선택 (완료)
- 요구사항: 공룡/정글/바다 테마 선택(및 작품 선택)을 TV가 아닌 **폰에서** 하도록 변경.
- 프로토콜에 `select-theme {theme}` / `select-artwork {theme, index}` 추가 — 서버는 기존 릴레이 경로로 그대로 중계(폰→TV).
- TV 홈 씬에서 테마 버튼 제거, "폰에서 테마를 선택하세요" 안내만 표시. `select-theme` 수신 시 calib 단계로 진입.
- 폰 컨트롤에 테마 3버튼 그리드 + 작품 칩 목록. 미접속 시 비활성화.
