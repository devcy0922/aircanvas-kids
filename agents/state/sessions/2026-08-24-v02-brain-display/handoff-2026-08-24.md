# Handoff — 2026-08-24 v0.2 아키텍처 리팩터링 (Phone=Brain / TV=Thin Display)

## 이 세션에서 무엇을 했나

사용자 요구: "폰에서 TV 찾기 → 테마/게임 패키지는 서버에서 다운로드 → 폰이 TV에 렌더링 내용 전달 → 폰은 카메라 모드 → 초기 손 인식(캘리브레이션) 후 게임 시작" 구조로 전환.

### 결정된 아키텍처
- **폰 = 브레인**: 패키지 다운로드/캐시, 게임 상태 머신, 손 추적, TV 탐색, 렌더 커맨드 송신.
- **TV = 씬 렌더러**: `TVCommand` 수신 실행만. 상태 없음. 기존 `GameEngine`(PixiJS)은 그대로 재사용.
- **서버**: 릴레이 역할 변화 없음(방 매칭 + 중계).
- **콘텐츠 서버(Nginx, :8081)**: `manifest.json` + SVG 썸네일. 신규 게임/테마는 여기만 고치면 됨(TV 코드 불변).

| 파일 | 역할 |

## 다음 세션이 반드시 알아야 할 것 (끊긴 부분)

1. **fill 미연결 (TASK-015)**: 폰의 "이 위치 채우기"가 `fill-region{regionId:'auto'}`를 보내지만 TV 핸들러는 regionId로 region을 찾으므로 동작 안 함. 프로토콜에 `fill-at {x,y,color}` 추가하고 TV에서 좌표 히트테스트하도록 해야 함.
2. **진행도 역방향 누수**: TV가 진행도를 계산해도 폰으로 돌아오는 경로 없음. `onProgressUpdate()`가 호출만 대기 중. 서버가 TV→같은 방 폰 릴레이는 이미 지원하므로 TV에서 progress 메시지 send만 추가하면 됨.
3. **디스커버리 실동작 조건 (TASK-016)**: Rust 서버에 `GET /announce` 핸들러 필요(JSON 응답). 또한 CORS `*` 헤더 필요 — 아니면 브라우저 fetch가 opaque로 차단됨.
4. **포트 충돌**: cy-server의 8080(GoVail)/8081(FLEVO) 점유. 로컬 검증 시 `HT_BIND=:18080 cargo run` + 모든 앱에 `?server=`/`?content=` 명시.
5. **TV roomCode 경로**: TV App은 현재 `?room=` 없으면 DEMO01. 디스커버리/QR로 받은 roomCode를 TV에 전달하는 UX 정리 필요.
6. **npm/cargo 환경(cy-server)**: `export NVM_DIR="$HOME/.nvm" && \. "$NVM_DIR/nvm.sh"` 후 Node 20 사용. cargo는 linux-gnu 기본 툴체인(package.json의 windows-gnu 스크립트와 무관).
